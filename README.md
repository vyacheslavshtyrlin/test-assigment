# Фаворит — поиск автозапчастей

Тестовое приложение на React и Redux Toolkit. Реализует двухэтапный поиск: сначала бренды по артикулу, затем складские предложения и аналоги по выбранному бренду.

## Архитектура

```text
src/
├── app/                         # композиция приложения и Redux store
├── pages/parts-search/          # сборка страницы поиска
├── features/parts-search/       # сценарий поиска, RTK Query, feature UI
├── entities/offer/              # нормализация и отображение предложений
├── widgets/header/              # самостоятельный блок шапки
└── shared/                      # API-адаптер, env, URL и общий UI
```

- Bootstrap 5 используется как базовый UI-слой: responsive grid, формы, кнопки, alerts, spinner и таблица. Визуальная тема и компонентные состояния задаются в `src/styles.css`.
- Межслойные импорты используют alias `@/`, настроенный одновременно в Vite и `jsconfig.json`; относительные импорты оставлены только внутри одного модуля.
- Параметры поиска хранятся в URL: `?number=W+914%2F2&brand=MANN-FILTER`.
- Прямые ссылки, Back/Forward и обновление страницы восстанавливают нужный этап поиска.
- RTK Query отвечает за запросы, короткий кеш, дедупликацию и отмену устаревших запросов.
- Локальное состояние формы не дублируется в Redux.
- Значения query-параметров нормализуются и кодируются через `URLSearchParams`; посторонние параметры, например UTM, сохраняются.
- Внешний Favorit API скрыт за одним клиентским интерфейсом с реальным и демонстрационным адаптерами.

## Запуск

```bash
npm install
npm run dev
```

Без `.env` приложение запускается в безопасном mock-режиме. Для реального API скопируйте `.env.example` в `.env`, укажите `FAVORIT_API_KEY` и установите `VITE_USE_MOCK_API=false`.

В development ключ читает только конфигурация Vite и добавляет его в запрос dev-proxy. Переменная намеренно не имеет префикса `VITE_`, поэтому ключ не попадает в клиентский bundle.

Документированный Favorit API использует HTTP. Для размещения собранного frontend нужен внешний HTTPS reverse proxy с маршрутом `/favorit-api`, который аналогично добавляет ключ на стороне инфраструктуры. Это deployment-контракт, а не часть React-приложения.

Ответ внешнего сервиса проходит runtime-валидацию. Запрос ограничен по времени и один раз повторяется при сетевом сбое или ответе `502/503/504`.

## Проверки

```bash
npm run lint
npm test
npm run build
```

Те же проверки выполняются в GitHub Actions для каждого push и pull request.

Цена берётся из `warehouses.price`, как предписывает документация API. Одна строка результата соответствует конкретному складскому предложению.
